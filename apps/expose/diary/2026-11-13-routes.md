### Rough

`web-build --out` makes a deployment build. Driving it failed with "the page
has no agent adapter". Setting `EXACT_WEB_DIST` instead gave the development
build its own directory, separate from the other apps' shared default dist.

`open` builds the declared chain for Reader and Settings shortcuts. Cross-screen
links use `push` to retain their caller, including About → Model and Reader →
Ask Expose. Every article and settings page's Back names the visit beneath
it, read with a `fn` over `stack(nav)`.

A conversation can be retained under another visit of the same thread (Add key,
then Talk to Expose). With one `id="composer"`, Send focused the covered field.
Each composer's id carries its visit's id, and Send focuses that one.

### Lean in

Declared parents give a directly opened conversation, article or settings page
its Back destination. In-app Back returns to the screen that opened it.
One root resource reads every thread id on the stack. Each retained conversation
selects its own record, keeping its transcript intact while Settings covers it.

### Needed

- deep links: provided by routes and the navigation root.
- browser history: provided by the router's history mirror.

### Checkpoints

- Editing app.contract: smooth; each screen is a retained route.
- Direct URLs and reload: pass for every screen and settings page.
- Browser transitions: pass for every conversation, article and settings page,
  including Ask Expose and the lock-screen notification action.
- Browser Back followed by app Back: pass across settings siblings, Ask Expose
  and a conversation's Add key action.
- Covered-thread content and shortcut Back destinations: pass in web drives.
- Linux renderer: compiles with the migrated routes.
- Apple navigation gestures: not run on this machine.
